# PostgreSQL Database 常用指令與操作指南

本指南整理了在開發環境中，與 PostgreSQL 互動最常使用的各類指令。涵蓋了 Docker 容器操作、連線工具 (`psql`) 以及一些 Postgres 特有的 SQL 語法與特性。

## 1. Docker 容器管理指令

我們在本地端是透過 Docker 運行 PostgreSQL 16 容器。

*   **啟動現有的 PostgreSQL 容器**
    ```bash
    docker start dot-net-mvc-web-postgres
    ```
*   **停止 PostgreSQL 容器**
    ```bash
    docker stop dot-net-mvc-web-postgres
    ```
*   **查看 PostgreSQL 容器運行狀態**
    ```bash
    docker ps -a | grep postgres
    ```

## 2. 進入資料庫 (使用 psql)

`psql` 是 PostgreSQL 官方的終端機連線工具。可以直接在 Docker 容器內執行它，進行資料庫操作。

*   **以應用程式專用使用者身份進入 psql**
    ```bash
    docker exec -it dot-net-mvc-web-postgres psql -U dot-net-mvc-web -d dot_net_mvc_web_db
    ```
*   **以系統管理員 (postgres) 身份進入 psql** (若需執行權限管理或建立使用者)
    ```bash
    docker exec -it dot-net-mvc-web-postgres psql -U postgres -d dot_net_mvc_web_db
    ```

### psql 內部常用快捷指令 (Meta-Commands)
當成功進入 `dot_net_mvc_web_db=> ` 或 `dot_net_mvc_web_db=# ` 提示字元後，可以使用以下系統指令：
*   `\q`：離開 psql 回到一般終端機。
*   `\l`：列出所有資料庫。
*   `\c [DBName]`：切換連線到其他資料庫。
*   `\dt`：列出目前資料庫中所有的資料表 (Tables)。
*   `\ds`：列出目前資料庫中所有的序列 (Sequences，如自動遞增主鍵使用)。
*   `\d [TableName]`：查看某張資料表的結構、欄位設計與關聯。
*   `\! clear`：清除畫面。

## 3. PostgreSQL 常用 SQL 指令

PostgreSQL 的 SQL 語法高度符合 ANSI SQL 標準，以下整理開發時最常用到的指令。

### 基本 CRUD 操作
*   **查詢資料 (注意：EF Core 建立的表通常需加雙引號)**
    ```sql
    SELECT * FROM "PostgresDemoItems";
    ```
*   **分頁查詢 (LIMIT / OFFSET 語法)**
    ```sql
    -- 略過前 10 筆，取接下來的 5 筆資料
    SELECT * FROM "PostgresDemoItems"
    ORDER BY "Id"
    LIMIT 5 OFFSET 10;
    ```
*   **新增資料**
    ```sql
    INSERT INTO "PostgresDemoItems" ("Name", "Description", "CreatedAt")
    VALUES ('測試名稱', '這是一段描述', CURRENT_TIMESTAMP);
    ```
    > 💡 **提示**：`CURRENT_TIMESTAMP` 或 `NOW()` 是 Postgres 取得當前系統時間的內建變數。

### 關聯查詢 (JOINs)
在 PostgreSQL 中，JOIN 語法與標準 SQL 相同。特別注意因為 EF Core 的關係，表名和欄位名通常需要加雙引號。

> 💡 **語法解析：資料表別名 (Table Alias)**
> 在下面的範例中，你會看到 `"PostgresDemoItems" i` 或 `"PostgresDemoCategories" c`。
> 這裡的 `i` 和 `c` 是為資料表取的**簡短代稱 (別名)**。

*   **INNER JOIN (內連接)**
    ```sql
    SELECT i."Name", c."Name" AS "CategoryName"
    FROM "PostgresDemoItems" i
    INNER JOIN "PostgresDemoCategories" c ON i."CategoryId" = c."Id";
    ```
*   **LEFT JOIN (左外連接)**
    ```sql
    SELECT i."Name", c."Name" AS "CategoryName"
    FROM "PostgresDemoItems" i
    LEFT JOIN "PostgresDemoCategories" c ON i."CategoryId" = c."Id";
    ```

### 子查詢 (Subqueries)
子查詢可以放在 `WHERE`, `SELECT`, 或是 `FROM` 中作為過濾條件或臨時表。
*   **WHERE 條件子查詢**
    ```sql
    SELECT * FROM "PostgresDemoItems"
    WHERE "CategoryId" IN (
        SELECT "Id" FROM "PostgresDemoCategories" WHERE "Name" = '測試分類'
    );
    ```
*   **EXISTS 子查詢** (通常效能較好，用於檢查關聯記錄是否存在)
    ```sql
    SELECT * FROM "PostgresDemoCategories" c
    WHERE EXISTS (
        SELECT 1 FROM "PostgresDemoItems" i WHERE i."CategoryId" = c."Id"
    );
    ```

### 不需要 FROM DUAL
與 Oracle 必須強制使用 `DUAL` 虛擬表不同，PostgreSQL 在不需要從資料表取資料時，可以**直接 SELECT**。
```sql
SELECT CURRENT_TIMESTAMP;
SELECT 1 + 1;
```

## 4. 常見問題與踩坑 (Gotchas)

1.  **區分大小寫 (Case Sensitivity)**
    在 PostgreSQL 中，如果建表時沒有加雙引號，所有的名稱都會被強制轉成**全小寫**。
    但因為我們使用的是 EF Core，EF Core 預設會幫我們對欄位和表名加上雙引號 (例如 `"PostgresDemoItems"`)，這會讓 Postgres 變成**嚴格區分大小寫**，保留了 C# 中的 CamelCase 命名。
    所以下 SQL 指令時，請務必記得加上雙引號：
    ```sql
    -- ❌ 錯誤 (因為沒加引號，會被 Postgres 轉成 postgresdemoitems 去找，結果報錯 relation does not exist)
    SELECT * FROM PostgresDemoItems;
    
    -- ✅ 正確
    SELECT * FROM "PostgresDemoItems";
    ```

2.  **IDENTITY 欄位與序列 (Sequences)**
    在 PostgreSQL 10+ 之後，建議使用 `GENERATED BY DEFAULT AS IDENTITY` 來實作流水號 (EF Core Npgsql 預設行為)。
    如果手動 Insert 了資料並且硬塞了 `Id` 值 (例如種子資料 `Id=1, 2`)，後續讓資料庫自動跳號時，可能會因為序列沒有跟著跳號而引發 Primary Key 重複 (`duplicate key value violates unique constraint`) 的錯誤。
    *解決方法*：如果有手動指定 Id，事後需要重置 Sequence (例如手動執行 `SELECT setval(pg_get_serial_sequence('"PostgresDemoItems"', 'Id'), coalesce(max("Id"), 1)) FROM "PostgresDemoItems";`)。
